# 응답하라 라디오 — 설계 결정·충돌 해결 기록 v0.7

문서 상태: 제안/설계 확정(구현 검증 아님). 본 문서는 이전 문서의 내용을 삭제하지 않고 우선순위를 기록한다.

1) 기존 결정 유지
	- ADR-001~006 (v0.1): 로컬 음원, AI의 비선곡 책임, 장애 시 기본 방송, 차량 UX, 개인정보 최소화, Music 하위 카테고리 가정.
	- ADR-007~010 (v0.2): 시대 우선, 2~3곡 블록, 독자적 DJ, 역할 분리.
	- ADR-011~016 (v0.4): 재생 단일 제어자, 순차 출력, 비동기 무효화, 시스템/사용자 일시정지 분리, 오류 안전.
	- ADR-017~021 (v0.5): 생성형 AI는 읽기 전용 방송 작가, LLM 출력 검증, 폴백, 서버 프롬프트 버전.
	- ADR-022~028 (v0.6): 컨텍스트의 시대 필터 우선, 블록 경계 반영, 날씨 TTL, 위치 비노출, UX 제약과 상황 분리, fingerprint.

2) 추가 결정
	2-1) ADR-029 — DJ 주기 우선순위
		- 사용자 최신 합의는 정상 완료된 2~3곡마다 DJ 등장. v0.1/기획 검토의 30분당 3회는 실제 곡 길이와 충돌하므로 강제 상한에서 제외.
		- 음원 1곡 반복/스킵만 반복 시 자동 DJ 남발을 막는 쿨다운 정책은 유지.
	2-2) ADR-030 — 데모 메타데이터 계약
		- 사용자가 MP3의 TITLE/ARTIST/YEAR를 준비하므로 외부 발매연도 조회나 AI 자동 추론은 제외. 태그 누락 시 미분류·안내의 방어 로직만 구현.
	2-3) ADR-031 — 날씨와 차량 상태를 분리
		- 현재 API의 허용 맥락은 시간대·날씨·이미 정해진 시대. 차량 데이터 활용은 런타임 접근·승인·차기 API 버전 전제.
	2-4) ADR-032 — API 하위호환 유지
		- v0.5 DJ API JSON Schema 1.0과 v0.6 ContextSnapshot 1.0을 수정하지 않는다. 현재 API에 없는 위치/차량/여행 목적을 임의로 추가하지 않는다.
	2-5) ADR-033 — TTS 완료 확인 실패 시 안전 정지
		- 출력이 중지됐는지 확인하기 어렵다면 음악을 중첩 재생하지 않는다. 플랫폼 TTS 콜백의 오류 타입과 포커스 동작을 우선 검증.
	2-6) ADR-034 — 문서/테스트/구현 완료 구분
		- CSV 테스트 상태는 기본 NOT_RUN. Fixture의 이벤트는 기대값이며 실제 테스트 성공을 뜻하지 않는다.
	2-7) ADR-035 — 시연 및 권리 분리
		- 사용자가 로컬 파일을 확보하더라도 영상·APK·공개 저장소에 포함할 권리는 별도 확인한다.

3) 남아 있는 설계 선택지(아직 확정하지 않음)
	3-1) `RadioPlanner` 선호/상황/다양성/반복 가중치: 실험 초기값 0.45/0.25/0.20/0.10. 곡 분위기 정보가 없으면 해당 항목을 제거하고 재정규화.
	3-2) 쿨다운 정량치: 1곡 반복 시 중간 DJ 생략, 2곡 이상의 서로 다른 곡 정상 완료 전에는 멘트 생략을 기본 권고. 사용성 테스트 후 최종 값 확정.
	3-3) DJ 오프닝 요청 지연: 미리 준비된 로컬 텍스트를 우선 사용해 첫 소리를 늦추지 않고, 온라인 생성은 초기 시연/재생 중에 검증.
	3-4) 날씨 API 공급사, 실제 위치 권한 안내, 공급사 상업 이용 정책.
	3-5) TTS 실제 모드/SDK 권한 및 차량 포커스 충돌 발생 시 대체 경로.
	3-6) Pleos Music vs Radio 하위 분류, 파일 선택기 지원 여부.

4) 개발 전 가장 먼저 해야 할 검증
	- P0: Play/MediaBrowser/Speaker, 파일 선택/권한 유지, TTS start/stop/callback, 주행 UX 제한.
	- 실패 결과를 Mock 성공으로 대체하지 말고 실제 리스크로 기록 후 기능 축소 결정.
