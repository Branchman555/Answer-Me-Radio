# 응답하라 라디오 — 길 위의 타임머신 추가 설계 v0.8

작성일: 2026-11-15 / 상태: 사용자 요청을 반영한 추가 설계안, 구현·권한·콘텐츠 배포 검증 전
기준: v0.7 통합 설계와 사용자 신규 제안. 본문에서 '제안'은 이번에 보완한 정책이며 사용자 최종 승인·실측을 뜻하지 않는다.

1) 결론과 제품 정의
	1-1) 기존 라디오에 '길 위의 타임머신'을 선택형 코너로 추가한다. 지역 안내 앱으로 교체하지 않는다.
	1-2) 목표 경험은 '현재 지나는 도로 구간 → 그 구간의 검증된 과거 기록 → 해당 시기의 음악 → 가족이 함께 듣는 레트로 DJ 방송'이다.
	1-3) 한 줄 소개: 응답하라 라디오는 지금 지나는 길의 옛 뉴스와 그 시절의 노래를 레트로 AI DJ의 한 편의 방송으로 엮어, 운전자와 동승자가 함께 추억을 나누는 차량용 라디오입니다.
	1-4) 사용자가 제안한 '아빠 차 뒷자리에서 듣던 라디오'를 기획 출발점으로 유지한다. 이는 기획자의 경험 서술이지 조사로 입증된 일반 사실은 아니다.
	1-5) 첫 고객은 가족 여행·귀성길의 40~50대 운전자라는 타깃 가설로 좁힌다. 세대 공감이라는 기존 목적은 유지한다. S1 통계는 연령·청취 장소의 근거이지 가족 여행 수요나 결제 의향을 증명하지 않는다.

2) v0.7과의 관계 및 변경 범위
	2-1) 유지: SINGLE/FAMILY, 로컬 MP3, TITLE/ARTIST/YEAR 기반 분류, 독자적 DJ, 정상 재생 2~3곡마다 발화, 음악/TTS 순차 출력, 단일 Orchestrator, 비동기 응답 차단, 사용자 PAUSE/STOP 우선, 날씨/시간 보조, 스트리밍은 제휴 후 확장.
	2-2) 추가: 구간 판별, 검수된 역사 콘텐츠 팩, 날짜 관련성 정렬, 사건 연도와 음원 매칭, 출처·선곡 근거 표시, 로컬 청취 기록 및 허용 상태의 다시듣기.
	2-3) 명시적 변경: v0.6의 '위치는 날씨 조회에만 사용'에서, 새 코너를 켜고 동의한 방송 세션에 한해 단말 내 구간 판별에도 사용한다. 원시 좌표의 서버 전송·상시 추적은 추가하지 않는다.
	2-4) 역사 코너는 20~30초를 목표로 한다. 일반 중간 멘트 10~20초 규칙은 그대로이며, 역사 코너가 일반 멘트를 대체한다. 두 종류를 연달아 붙이지 않는다.
	2-5) '방송 기록'은 들었던 코너의 출처를 확인하는 로컬 기록이며, 후속으로 남겨 둔 '우리의 카세트' 제작·공유 기능과 다르다.
	2-6) v0.5 DJ API와 v0.6 ContextSnapshot 스키마는 바꾸지 않는다. 새 사실 필드를 기존 API의 free text로 끼워 넣지 않는다. 콘텐츠 팩은 별도 로컬 계약이다.
	2-7) 사용자 수정 중인 공식 Word는 덮어쓰지 않는다. 제출 반영용 문구를 별도 Markdown으로 제공한다.

3) 모드와 시대 우선 원칙
	3-1) 기본값은 기존 방송 그대로다. 새 옵션 `roadTimeTravelEnabled`는 초기 false이며 사용자 명시 선택으로 켠다.
	3-2) 옵션 안내: '지나는 길의 이야기가 나오면 잠시 그 사건의 연도로 이동합니다.' 사용자가 켜면 역사 코너에 한해 `FOLLOW_STORY_YEAR` 정책이 적용된다. 기본 설정의 시대 목록을 영구 변경하지 않는다.
	3-3) 기존 방송: 선택한 시대 → 사용자 취향 → 유효한 날씨/시간/다양성. 기존 하드 필터를 유지한다.
	3-4) 역사 코너: 현재 도로 구간과 직접 연결된 기록 → 같은 월·일 우선 → 검증된 사건의 연도 → 그해의 재생 가능한 로컬 곡 → 취향과 상황 순으로 처리한다.
	3-5) 사건 연도가 2001년이면 해당 코너의 `allowedYearRange=[2001,2001]`이다. 기존 1980s/2010s 방송에 임의로 2001년 곡을 끼워 넣는 것이 아니라 사용자가 선택한 특별 코너 정책으로 명시한다.
	3-6) 코너 종료 후 저장해 둔 기본 방송 큐·세대 순서로 복귀한다. 해당 연도 곡이 하나도 없으면 MVP에서는 코너 자동편성을 생략하고 기존 방송을 유지한다. 같은 분위기라는 이유로 다른 연도/시대의 곡을 자동 대체하지 않는다.
	3-7) 추가 선택지 '선택 시대 밖으로 이동하지 않기'는 후속 검토. 초기 버전에서는 명시적 ON/OFF 한 가지로 복잡도를 제한한다.

4) 장소·날짜·음악 근거를 분리한다
	4-1) 기록 필수 항목: storyId, canonicalEventId, 장소 이름, 실제 사건 날짜, 기사 게시 날짜, 도로 구간 식별자, 검수된 사실 문장, 출처 ID, 검수 상태, 콘텐츠 버전.
	4-2) 기사 게시일을 사건 발생일로 대체하지 않는다. 같은 월·일 비교는 사건 날짜와 사용자의 현지 날짜로 수행한다. 시계가 불명확하면 기념일 우선 기능만 끈다.
	4-3) 선별 순서: 검수 완료·이용 범위 확인 → 실제 통과 구간 매칭 → 이번 이동에서 아직 재생하지 않은 사건 → 오늘과 같은 월·일 → 그 구간의 다른 검증된 기록.
	4-4) 날짜 일치를 맞추려고 다른 지역의 사건을 가져오지 않는다. 동일 사건의 다른 기사도 canonicalEventId로 중복 제거한다. 정확한 사건일이 미상인 기록은 MVP 자동편성에서 제외한다.
	4-5) 역사 대상 공간과 오늘의 도로를 연결하는 지오메트리는 기사와 별개로 검증한다. 옛길·신도로·평행 국도·양방향을 한 점 반경만으로 동일 구간이라 판정하지 않는다.
	4-6) 선곡 근거 분류:
		BROADCAST_VERIFIED: 특정 방송·날짜의 실제 선곡표가 확인된 경우. 방송명과 날짜를 함께 표시한다. 당시 이 도로에서 방송됐다는 의미는 아니다.
		CHART_VERIFIED: 당시 차트명·집계 기간·곡이 확인된 경우. '그 시절 인기곡'으로 표시한다. 곡 발매일만으로 이 라벨을 부여하지 않는다.
		RELEASE_PERIOD: 발매연월 또는 연도만 확인된 경우. '같은 달 발표곡' 또는 '같은 해 발표곡'으로 표시한다.
		ERA_ONLY: 연대만 맞는 관계. 이번 MVP의 사건 연도 하드 필터에서는 자동편성하지 않으며 향후 정책 확장 시에도 인기·실제 방송으로 표시하지 않는다.
	4-7) 로컬 YEAR만 있으면 연 단위까지만 말한다. 월·일과 차트·선곡표는 별도 검수 메타데이터가 있을 때만 사용한다. AI가 날짜 정밀도를 높이거나 차트 성적을 보충하지 않는다.
	4-8) 사건일보다 뒤에 발표된 것이 확인된 곡은 당시 이용 가능했던 곡처럼 소개하지 않는다. 날짜 정밀도가 낮아 선후를 확정할 수 없다면 '같은 해 발표곡'만 허용하고 당시 실제 청취를 주장하지 않는다.

5) 위치 트리거와 재생 시점
	5-1) 실제 위치는 FusedLocation의 변경 콜백으로 받되 마지막 위치 조회를 새로운 실시간 위치로 간주하지 않는다. API·권한 관련 근거는 S6·S7이며 배경 실행·단말 지원은 별도 검증한다.
	5-2) LocationAdapter는 위치의 측정 시각·정확도·유효성·권한을 정규화한다. 단말이 이를 제공하지 않아 실제 구간을 신뢰성 있게 판별할 수 없다면 자동 재생을 막고 `UNKNOWN`을 반환한다.
	5-3) SegmentMatcher는 승인된 구간 지오메트리, 연속 위치, 필요한 경우 이동 방향/경로 정보를 함께 사용한다. 경로에 포함됐다는 사실은 사전 준비에만 쓰고 실제 진입 증거로 쓰지 않는다.
	5-4) 반경/연속 표본 수/체류 시간은 도로 특성과 갱신주기를 측정해 조정할 제안값이다. 기본 제안은 유효한 연속 표본 2개, 측정 시각 10초 이내, 정확도 50m 이내이나 이것만으로 평행도로 구분을 보장하지 않는다.
	5-5) 진입하면 자동 발화가 아니라 pending 코너를 등록한다. 사용자 재생 의도가 true이고 실제 음악을 듣는 세션에서만 동작한다. 앱을 켜기만 했거나 PAUSED/STOPPED이면 진입만으로 말하지 않는다.
	5-6) 기본 발화 시점: 최근 DJ 이후 2곡 이상 정상 완료 + 곡 경계 + 오디오 포커스 확보 + 여전히 해당 구간/유효한 위치 + 과다 발화 제한 충족. 2곡째 경계에서 역사 코너를 선택할 수 있고, 후보가 없으면 기존 3곡 기준으로 진행한다.
	5-7) 음악 도중 진입해도 음악을 끊지 않는다. 현재 DJ도 겹쳐서 중단·교체하지 않는다. 새 코너는 보류하고 유효한 다음 경계에만 선택한다.
	5-8) 발화 전에 구간을 벗어나거나 위치가 오래되면 pending을 취소한다. 음악이 끝나기 전에 장소를 지나친 경우 자동 코너를 생략할 수 있다. 따라서 '그 지점을 지나는 바로 그 순간 반드시 발화'는 구현 보장 문구로 쓰지 않는다.
	5-9) pending은 최대 1개다. 더 적합한 신규 구간이 확인되면 미발화 후보만 교체한다. 오래된 위치 코너를 줄 세워 나중에 한꺼번에 들려주지 않는다.
	5-10) 기본 중복 키는 `(tripSessionId,canonicalEventId)`다. 자동 발화 시작을 기록해 중단 후 재진입 시 반복하지 않는다. 사용자 요청의 다시듣기는 별도 행동이다.
	5-11) 방송 중 새 좌표가 올 때마다 generation을 증가시키지 않는다. 코너 선택 확정/취소/경로 후보 변경 시에만 전이 소유자가 필요 버전을 갱신한다.

6) 뉴스와 음악을 연결하는 방송 블록
	6-1) `기본 음악 2~3곡 → 역사 DJ 20~30초 → 사건 연도 음악 2~3곡 → 기본 세대 방송 복귀`가 제안 흐름이다. 역사 DJ는 일반 DJ를 대체한다.
	6-2) 사건 연도에 1곡뿐이면 축약 블록으로 재생하되 바로 다음 DJ를 붙이지 않는다. 전역 정상 완료 카운터가 다시 2곡 이상이 될 때까지 기본 방송 음악으로 이어간다.
	6-3) 코너 종료 후에도 기존 가족 모드의 다음 시대 커서를 유지한다. 중간에 미재생인 원래 곡을 이미 들은 곡으로 기록하거나 건너뛴 곡을 정상 종료로 세지 않는다.
	6-4) 코너에서 소개할 곡은 대본 발화 직전에 로컬 접근 가능 여부를 다시 검사한다. 권한 철회·USB 제거로 재생이 불가능해지면 해당 곡 소개를 발화하지 않고 코너를 생략한다.
	6-5) 음악 선택과 URI·재생 명령은 Planner/Orchestrator만 소유한다. LLM이 임의 곡을 요청하지 않는다.
	6-6) DJ OFF면 역사 발화도 OFF다. 위치 코너는 기본 음악을 덜 방해해야 하며, 켜지 않은 위치 기능이 계속 위치를 받지 않도록 구독 수명을 관리한다.

7) 대본 제작 및 AI의 한계
	7-1) 입력 자료는 담당자가 검수한 `facts[]`와 근거가 확인된 `musicAssociations[]`뿐이다. 주행 중 웹 검색·기사 크롤링·원문 자동 수집은 MVP에서 하지 않는다.
	7-2) 추천 구현은 역사 대본을 사전 AI 생성 → 사실·표현·시제·길이 담당자 검수 → 콘텐츠 팩 저장 → 구간 진입 시 TTS 재생이다. 현재 실시간 일반 DJ 생성은 기존 v0.5대로 유지한다.
	7-3) 당시 뉴스 원문이나 원본 앵커 음성을 재생하지 않는다. 사건의 날짜·장소·사실을 짧게 재구성한다. '오늘 개통됐습니다' 같은 현재 뉴스로 오인할 표현 대신 실제 과거 날짜를 말한다.
	7-4) 출처 ID와 JSON 스키마의 통과만으로 사실성이 보장되지 않는다. 검수된 사실 문장 고정·숫자 및 고유명사 대조·사람의 콘텐츠 검수가 필요하다.
	7-5) fallback은 같은 사실의 검수된 짧은 대본이다. 대본이 없거나 TTS가 실패하면 기존 정책대로 음악만 재생한다. 확인되지 않은 역사 사실을 일반 멘트로 즉석 보충하지 않는다.
	7-6) 초기는 개통·지역 행사·문화시설 변화 등 비교적 중립적인 기록으로 제한한다. 참사·사망·범죄 등을 가벼운 향수 코너로 자동 편성하지 않는다. 실존 DJ 음성·고유 방송 시그널 복제는 제외한다.
	7-7) 향후 실시간 역사 대본 생성이 필요하면 별도 버전 계약을 제안한다. 기존 `/api/v1/dj/scripts`의 enum/추가 필드를 몰래 바꾸지 않는다. 이번 버전에는 새 서버 endpoint를 확정하지 않는다.

8) NaviHelper, 안전 UX, 길이 조절
	8-1) 목적지 정보는 getDestinationInfo/onDestinationInfo로 조회하고, remainTime 필드 존재는 S8·S10에서 확인한다. 단위·미설정 값·신선도·단말 권한이 확인될 때만 `remainingSeconds`로 변환한다.
	8-2) 권한은 조회 기능에 필요한 범위만 검토한다. 음악 코너를 위해 목적지·경로를 변경하거나 NAVI_ROUTE_SEARCH를 당연히 요구하지 않는다(S9).
	8-3) 목적지 미설정·NaviHelper 미지원·시간 단위 미검증이면 ETA는 null이며 일반 길이를 사용한다. 음원 길이로 도착 시간을 계산하거나 현재 속도만으로 추정하지 않는다.
	8-4) 초기 제안값: 목적지까지 3분 미만이면 사실 1~2문장의 8~12초 축약본, 30초 미만이면 새 역사 코너 생략. 이 수치는 UX 실험값이지 안전 인증 기준이 아니다. 도착 전 곡 전체 재생을 보장하지 않는다.
	8-5) 통화·내비·차량의 상위 오디오 정책 우선, TTS 중지 완료 확인, 단일 출력, 사용자 일시정지 상태 복구 금지를 그대로 적용한다. 내비 안내가 시작되기 전을 알 수 있다고 가정하지 않는다.
	8-6) 상세 출처·기록 탐색·다시듣기는 플랫폼이 허용하는 상태에서 제공한다. 단순 속도 0이나 교차로 정지를 주차로 간주하지 않는다(S12).

9) 위치·기록·콘텐츠 운영
	9-1) 도로 매칭은 단말에서 수행한다. 원시 좌표·이동 경로·정확한 진입 시각·차량 식별자를 LLM·진단 로그·서버로 전송하지 않는다.
	9-2) 장소 ID도 이용 시각과 연결하면 이동을 유추할 수 있다. 위치가 포함된 실시간 콘텐츠별 서버 호출을 피하고 사전 콘텐츠 팩/대본을 활용한다. 좌표 제거만으로 익명이라고 주장하지 않는다.
	9-3) 위치 사용 동의·철회는 날씨와 길 위 코너의 목적을 구분해 안내한다. 철회 시 길 코너 후보와 구독을 해제하고 기본 방송은 유지한다. 상세 법적 요건은 서비스 배포 형태 확정 후 별도로 검토한다.
	9-4) 청취 기록은 로컬에 storyId·콘텐츠 버전·재생 상태·순서만 보관한다. 정밀 좌표와 상세 이동 시각은 보관하지 않는다. 현재 이동 중 50건 상한, 최대 7일 후 삭제 및 사용자 전체 삭제를 초기 제안으로 둔다.
	9-5) 지도상 도로 구간 데이터의 공급원·갱신·라이선스도 콘텐츠 권리와 별도로 확인한다. 기사의 사실 확인은 현재 도로 지오메트리 검증을 대체하지 않는다.
	9-6) 기사 내용이 공개되어 있다고 원문·영상·음성·사진의 재사용 허락까지 확보된 것은 아니다. 사실과 창작 표현의 구분은 S13을 참고하고 개별 이용조건을 확인한다. AI 학습 데이터로 과거 방송 원문을 모으는 작업은 포함하지 않는다.
	9-7) 정정·철회: 콘텐츠 version을 증가시키고 해당 storyId와 캐시 대본을 비활성화한다. 과거 청취 기록의 다시듣기도 철회 상태를 확인한다. 대량 저장·검색 API·지도 라이선스 계약은 각각 검토한다.

10) 추가 모듈 — 기존 재생 엔진 재사용
	10-1) LocationAdapter: 위치 수신/권한/측정 시각 정규화. 정밀 데이터는 여기와 로컬 매칭 경계 안에만 둔다.
	10-2) RoadSegmentMatcher: 검수된 구간 데이터로 현재 통과 여부를 CONFIRMED/UNKNOWN/OUTSIDE로 판정. UNKNOWN이면 발화 금지.
	10-3) HistoricalStoryRepository: 검수 사실·날짜·출처·대본·음악 근거·이용범위 저장. 이번에는 수동 관리 콘텐츠 팩이며 별도 CMS 구축은 제외.
	10-4) RoadStoryPlanner: 구간 및 날짜 우선순위, 사건 연도 하드 필터, 음원 가용성 검사. 선택된 결과만 반환.
	10-5) RoadStoryScriptProvider: 승인된 LONG/SHORT 역사 대본을 반환. 새 JSON 계약을 기존 DJ API에 전송하지 않음.
	10-6) StoryHistoryRepository: 로컬 출처·재생 상태와 사용자 삭제. 카세트 공유와 분리.
	10-7) RadioOrchestrator: 위 결과를 받아 기존 단일 상태 머신에서 실행. 별도 Player나 독립 위치 방송 서비스를 추가하지 않음.

11) 동시성·무효화 규칙
	11-1) 새 로컬 pending 메타데이터는 storyId, canonicalEventId, contentVersion, tripSessionId, segmentId, matchRevision, expiresAtMonotonic, chosenTrackIds, cachedScriptId, baseQueueCheckpoint다.
	11-2) sessionId/generation/playbackEpoch의 기존 검사를 유지하고, 코너 후보의 contentVersion/matchRevision/유효 공간을 발화 직전에 검사한다. 구독 콜백이 직접 TTS.play를 호출할 수 없다.
	11-3) 재탐색·우회가 확인되면 아직 말하지 않은 후보를 취소한다. 코너 재생 중 경로가 바뀌어도 음악을 급히 자르지 않고 다음 코너부터 갱신한다.
	11-4) PAUSE/STOP/NEXT/DJ OFF가 우선한다. DJ 중 NEXT는 코너 음성만 건너뛰고 소개 예정 곡까지 이중 스킵하지 않는다. 단, 곡이 무효하면 기존 오류 복구 정책으로 이동한다.
	11-5) 역사 음성 시작 후 중단된 코너는 PARTIAL로 남기고 자동으로 처음부터 반복하지 않는다. 원하면 허용 상태에서 사용자가 다시듣기를 누른다.
	11-6) 캐시 만료나 콘텐츠 철회로 장치에 유효 대본이 없으면 음악 유지. 기사 재검색으로 재생을 블로킹하지 않는다.

12) 데모 범위와 작업 분담
	12-1) 1개 이동 코스, 3~5개 검증 기록, 기록 연도와 일치하는 사용자 로컬 MP3로 범위를 제한한다. 이 수량은 제안이며 현재 확보 완료 수량이 아니다.
	12-2) 사용자가 음원·필수 메타데이터를 준비한다는 기존 분담을 유지한다. 월·일 근거가 필요한 코너만 별도 카탈로그 정보를 추가한다.
	12-3) 기획 담당: 장소·사건 날짜·게시 날짜·출처·사실 요약·선곡 근거·공개 시연 권리 체크. 개발 담당: 위치 신뢰성·구간 매칭·편성·재생·SDK 검증.
	12-4) 실제 구간 데이터와 위치 공급이 검증되기 전에는 모의 궤적 테스트로 우회/재진입/오류를 검증한다. 화면·시연에 모의 이동임을 표시하며 실차 검증 성공으로 표시하지 않는다.
	12-5) 아래 콘텐츠 예시는 사건·음악 카탈로그 근거만 조사한 초안이다. 실제 구간 지오메트리·음원 파일·콘텐츠 이용권·대본 담당자 승인이 없으므로 기본 실행 불가로 둔다.

13) 검증된 예시와 표현
	13-1) 대관령 사례의 사건 날짜는 2001-11-28이며 MBC 당시 보도로 확인한다(S3). 도로 좌표를 본 문서에서 임의 생성하지 않는다.

14) 완료 조건과 미검증 사항
	14-1) 기존 인수 테스트 54개는 그대로 보존한다. 신규 테스트는 별도 파일에 NOT_RUN으로 추가하며 실제 실행 결과가 아니다.
	14-2) 우회·평행도로·오래된 위치·권한 거부에서 오발화하지 않아야 한다. 실제 지오메트리 검증 없이 '정확히 지나갈 때 재생'을 완료로 표시하지 않는다.
	14-3) 2~3곡 규칙과 코너의 공간 유효성이 동시에 맞지 않으면 생략하는 보수적 정책을 먼저 검증한다. 생략률이 높으면 콘텐츠 구간 길이와 사전 준비를 개선하고, 음악 강제 중단으로 해결하지 않는다.
	14-4) 역사 사실·선곡 라벨·신구 도로 연결·공개 시연 권한·TTS 길이·위치 배경 동작·NaviHelper 단위를 각각 검증한다.
	14-5) 지표는 구간 매칭 오탐률, 유효 코너 재생률, 중복 자동발화 수, 사실/라벨 오류 수, 코너 건너뛰기 비율, 동승자 대화 계기 평가로 정의한다. 아직 실측 수치 없음.
