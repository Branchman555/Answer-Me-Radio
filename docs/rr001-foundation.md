# RR-001 구현 경계

이 문서는 RR-001 완료 당시 범위다. 이후 상황정보·일반 DJ 계약과 선행 요청 연결은 [RR-002](rr002-context-dj.md)에서 구현했으며 최신 상태는 [Archive](../Archive.md)를 따른다.

## 소유권

`planner/RadioPlanner.kt`가 시대 범위와 음악 순서를 결정한다. `orchestrator/RadioReducer.kt`는 불변 상태와 이벤트를 받아 새 상태·effect만 반환한다. `demo/Simulation.kt`의 직렬 이벤트 큐가 Fake 출력을 실행하고 중지 완료를 다시 이벤트로 전달한다. UI는 Player/TTS를 직접 호출하지 않는다.

`story/StoryContent.kt`는 v0.8 팩 JSON의 필드·타입·날짜·출처 ID·대본 참조를 검사한다. `RoadStoryPlanner.kt`는 승인 상태와 최신 버전, 같은 구간, 사건 날짜, 음원 연도를 검사한다. 최신 철회 버전은 이전 승인 버전을 가린다. 동일 버전의 충돌은 실행하지 않는다.

구간 결과는 로컬 어댑터 계약 `SegmentMatch`다. 현재 실제 GPS/지오메트리 구현은 없다. Fake는 명시적으로 만든 가상 구간만 전달한다. 이름이 CONFIRMED인 값만으로 충분하지 않으며 지오메트리 검증·평행도로 구분·연속 표본·10초 신선도도 요구한다. 실제 정확도 검증은 위치 어댑터의 책임으로 남아 있다.

## 이번 결정

- 단일 Android app 모듈을 유지한다. 기존 Revia는 소스 의존성이 아니며 로컬 JDK와 wrapper 배포 도구만 재사용했다.
- 선호 장르와 최근 곡/아티스트만 사용하고 분위기 정보 없는 곡의 날씨 점수는 만들지 않는다. 실험용 가중치 최적화는 도입하지 않았다.
- 로컬 출력은 아직 무음 Fake다. 단일 출력 검증은 Fake의 물리 출력 슬롯과 Reducer의 토큰으로 수행한다. 장치 오디오 중첩 검증이 아니다.
- 원본 스키마에 방송명·방송일/차트명·집계 기간이 없으므로 BROADCAST_VERIFIED/CHART_VERIFIED를 이번 런타임에서 활성화하지 않는다. RELEASE_PERIOD만 허용한다. 기존 스키마를 몰래 확장하지 않고 향후 검수 근거 계약이 확보되면 지원한다.
- 역사 코너는 같은 해의 검수 음악 연결을 최대 3곡 사용한다. 소개하는 곡이 첫 곡이며 내용 검수는 사람의 승인에 의존한다. JSON 통과로 역사 사실이나 문장의 정확성을 자동 증명하지 않는다.
- 별도 서버·네트워크 권한·실제 위치 권한은 없다. 일반 AI 대본은 상관관계 캐시 검사까지만 구현했다. 공급자 검증/선행 요청/타임아웃 연결 전이므로 캐시 문장을 실제 발화하지 않는다.
- 코너 기록은 프로세스 내 최대 50건이며 정확한 이동 시각/좌표를 저장하지 않는다. 삭제해도 현재 trip의 중복 방지 집합은 유지한다. 영속 보존·7일 만료·다시듣기는 RR-008이다.

## 남은 동작

실제 음악 위치 보존/이전 곡(PREVIOUS), 플랫폼 포커스 획득, 실제 비동기 stop timeout 스케줄러, MediaSession, SAF, TTS, ContextSnapshot과 백엔드는 아직 없다. 앱 화면은 개발 조작 화면이며 차량 운전 중 사용 승인을 받거나 안전 UX를 구현한 화면이 아니다. 모의 로직 검증과 APK 빌드를 실제 재생·실차 시험으로 보고하지 않는다.

## 검증

`app/src/test/kotlin/radio/reply/`의 JUnit 테스트가 선곡·기본 전이·역사 게이트·이벤트 순서 경합을 검사한다. 테스트 이름의 AC/RS 번호는 관련 설계 항목 연결이며 원본 인수 테스트 전체 PASS를 뜻하지 않는다. 원본 테스트 파일은 수정하지 않으며 실행된 테스트 이름과 결과는 `evidence/latest.json`에 별도로 수집한다.
